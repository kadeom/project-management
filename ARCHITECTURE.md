# Архитектура

Описание по мотивам arc42: цель, границы, решение и элементы. Детали — в
[`docs/architecture/`](docs/architecture/README.md), решения — в
[`docs/architecture/adr/`](docs/architecture/adr/README.md).

## 1. Введение и цели

Тулкит собирает комплект лабораторных работ по MS Project из одного файла
`project.yaml`. Студент меняет данные проекта, запускает `build.py` и получает
согласованный набор артефактов: XML, расчёты, отчёт и готовые `.mpp` (на
Windows). Второй конвейер, `build_infosec.py`, собирает два варианта дополнительного
задания (PAM и DLP+SIEM) из отдельных YAML.

Цели:

- один источник данных вместо ручного дублирования задач и ресурсов;
- воспроизводимая сборка без MS Project;
- независимая проверка расчётов через планировщик MPXJ;
- готовый отчёт с таблицами и местами под скриншоты;
- общий расчёт для основного проекта и дополнительного задания.

## 2. Ограничения

- Python 3.10–3.14. Потолок задаёт JPype1 1.7.1.
- MPXJ 16.10.0 и JPype1 1.7.1 закреплены точно: XML зависит от версии writer.
- Генерация XML требует JVM (Java 8+). Режим `--no-xml` работает без Java.
- `.mpp` создаёт только MS Project через COM. Это Windows-only и не входит в CI.
- Сборка детерминирована: одинаковый вход даёт побайтово одинаковый XML и JSON.
- Сеть при сборке не нужна.

## 3. Контекст и границы

```text
project.yaml ─────────────► build.py ──┐
additional-assignment/*/project.yaml ─► build_infosec.py ─┤
                                                      ▼
                                                   src/pm
                                                      │
       ┌──────────────────────────────────────────────┤
       ▼                                              ▼
 out/*.xml ──► MS Project ──► .mpp          out/expected.json, out/analysis.md
       │                                              │
       └──────────────► out/*.docx ◄──────────────────┘
```

Внутри: модель, CPM, MPXJ-выгрузка, анализ, отчёт, пути.
Снаружи: MS Project, JVM/MPXJ, Word-совместимый просмотрщик, Windows COM.

Границы автоматизации — в [`docs/architecture/boundaries.md`](docs/architecture/boundaries.md).

## 4. Стратегия решения

1. **Один источник.** `project.yaml` — контракт данных. Модель загружает его и
   проверяет инварианты.
2. **Независимый расчёт.** `cpm.py` считает сроки, резервы и стоимость без MPXJ.
   XML проверяется тем же входом через MPXJ, расхождения ловят тесты.
3. **SSOT путей.** `paths.py` хранит имена артефактов и `MANIFEST`. Литералы в
   скриптах запрещены.
4. **Run from source.** `build.py` добавляет `src/` в `sys.path`. Установка не
   обязательна, ВМ работает из клона.
5. **Один источник текста отчёта.** `report.blocks()` строит блоки, из которых
   получаются Markdown и `.docx`. `shots()` извлекает метки скриншотов.
6. **Лучшее усилие для UI.** Падение COM-шага не должно ломать расчётную часть.
7. **Один пакет — два конвейера.** Дополнительное задание переиспользует
   `model`, `cpm`, `analysis`, `msproject` и `paths`; отличается только YAML,
   валютный слой и отчёт.
8. **Курс валют — данные, не запрос.** Сборка не ходит в сеть; `fx` хранится
   в YAML и обновляется вручную через `scripts/fx_rate.py`.

## 5. Строение

| Компонент | Ответственность | Не делает |
|---|---|---|
| `src/pm/model.py` | разбор YAML, WBS, связи, ресурсы | не считает сроки |
| `src/pm/cpm.py` | календарь, CPM, резервы, перегрузки, стоимость | не пишет XML |
| `src/pm/msproject.py` | MSPDI XML, планировщик MPXJ, чтение обратно | не строит отчёт |
| `src/pm/analysis.py` | PERT, сценарии сокращения, сводки | не форматирует Word |
| `src/pm/report.py` | блоки отчёта, Markdown, `.docx` | не считает проект |
| `src/pm/paths.py` | пути, имена, манифест | не содержит логики |
| `src/pm/currency.py` | курсы НБКР/ЦБ РФ, пересчёт сметы | не строит отчёт |
| `src/pm/report_infosec.py` | блоки и `.docx` дополнительного задания | не считает CPM |
| `build_infosec.py` | оркестрация двух вариантов ДЗ | не дублирует расчёты |
| `build.py` | оркестрация, CLI, `--full` | не дублирует расчёты |
| `automation/` | COM/UIA, скриншоты, вставка PNG | не меняет модель |
| `tests/test_pm.py` | инварианты, покрытие ЛР, XML, ссылки | не заменяет ревью |

## 6. Сценарии сборки

| Команда | Что делает | Зависимости |
|---|---|---|
| `python build.py` | XML, расчёты, отчёт | Python + Java |
| `python build.py --no-xml` | JSON, Markdown, `.docx` | Python |
| `python build.py --full` | всё выше + `.mpp`, скриншоты | Windows + MS Project |
| `python build_infosec.py` | `.md`, `.docx`, два XML ДЗ | Python + Java |
| `python build_infosec.py --full` | всё выше + `.mpp`, 10 скриншотов | Windows + MS Project |

## 7. Артефакты

Исчерпывающий список — `MANIFEST` в `src/pm/paths.py`. В `out/` лежат семь
XML-вариантов, семь `.mpp`, `expected.json`, `analysis.md` и отчёт `.docx`.
Дополнительное задание добавляет `infosec_v12_full.xml` и `infosec_v10_full.xml`.
`.mpp` не входит в `MANIFEST`: это бинарный артефакт MS Project, а не результат
Python-сборки.

## 8. Качество и безопасность

- `pytest` проверяет модель, покрытие требований ЛР, CPM, XML, детерминизм,
  ссылки, блоки ДЗ и пересчёт валют.
- `ruff` и `bandit` ловят дефекты, а не стиль. Основания — в
  [`docs/reference/security-notes.md`](docs/reference/security-notes.md).
- Вход `project.yaml` считается доверенным. XML парсится только собственный,
  поэтому `defusedxml` не подключён.
- Секретов в репозитории нет. Сетевые вызовы при сборке отсутствуют.

## 9. Риски

| Риск | Мера |
|---|---|
| Смена версии MPXJ меняет XML | точный пин и тест детерминизма |
| Нет JVM на ВМ | `--no-xml` и понятная ошибка |
| COM-автоматизация хрупкая | шаги изолированы, есть ручной чек-лист |
| `out/` расходится с моделью | тесты ссылок и `MANIFEST` |
| Большие бинарные `.mpp` в git | решение зафиксировано в ADR-0004 |
| Курс валют устарел | блок `fx` с датой и источником, ручное обновление |
| Регистрация в Jira требует почты | `JIRA_SIGNUP_EMAIL`, creds не коммитятся |
