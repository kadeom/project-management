# Границы автоматизации

## Машина считает

`src/pm` детерминированно строит расписание, стоимость, PERT и XML. Результат
воспроизводим: тот же `project.yaml` и те же версии дают тот же `out/`.

## Машина готовит

`build.py` собирает отчёт и места под скриншоты. `build_infosec.py` делает то же для
двух вариантов дополнительного задания. `automation/` может снять экраны в
MS Project на Windows. Это вспомогательный слой, а не источник истины.

## Человек проверяет

- открывает XML или `.mpp` в MS Project;
- сверяет даты, критический путь, перегрузки и стоимость с `analysis.md`;
- делает ручные действия из `guides/checklist.md`;
- отвечает на вопросы защиты и подписывает отчёт.

## Что не автоматизируется

- установка MS Project и Java;
- проверка того, что преподаватель примет формулировки;
- ручные задания методички, где требуется создать пустой проект;
- смысловая оценка отчёта.

## Уровни доверия

| Артефакт | Доверие | Проверка |
|---|---|---|
| `project.yaml` | вход | модель и тесты |
| `out/*.xml` | вычислено | MPXJ + MS Project |
| `out/expected.json` | вычислено | тесты CPM |
| `out/analysis.md` | производное | ссылки и модель |
| `out/*.docx` | производное | визуальная проверка |
| `.mpp` | производное MS Project | открыть в MS Project |
| `additional-assignment/*/Доп_*.docx` | производное | визуальная проверка |
| `docs/reference/infosec/prices.md` | справка | сверка с `cost_basis` |
