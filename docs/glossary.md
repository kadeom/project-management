# Glossary of abbreviations

Repository paths and identifiers use English terms. Russian prose may keep the
expanded form, but file names, modules and artifact IDs are English.

| Identifier | Expansion | Russian source |
|---|---|---|
| `infosec` | information security | СЗИ — система защиты информации |
| `lab` | laboratory work | ЛР — лабораторная работа |
| `conf` | conference | KONF — конференция |
| `assignment` | additional assignment | ДЗ — домашнее задание |
| `guidelines` | methodological guidelines | МУ — методические указания |
| `pam` | privileged access management | — |
| `dlp` | data loss prevention | — |
| `siem` | security information and event management | — |
| `kgs` | Kyrgyz som (ISO 4217) | — |
| `cpm` | critical path method | — |
| `pert` | program evaluation and review technique | — |
| `wbs` | work breakdown structure | СДР — структура декомпозиции работ |
| `mspdi` | Microsoft Project Data Interchange | — |
| `mpp` | Microsoft Project binary file | — |

## Rules

- Do not use transliterated Russian abbreviations in identifiers: `szi` →
  `infosec`, `lr` → `lab`, `konf` → `conf`.
- A new abbreviation is added here with its expansion.
- Russian prose may use the expanded Russian term, for example
  «система защиты информации», instead of a bare abbreviation.
