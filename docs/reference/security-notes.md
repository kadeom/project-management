# Безопасность и качество

## Границы доверия

| Вход | Доверие | Почему |
|---|---|---|
| `project.yaml` | доверенный | редактирует владелец репозитория |
| `out/*.xml` | свой вывод | парсится после собственной сборки |
| `.docx` | свой вывод | генерирует python-docx |
| `project-management-guidelines.docx` | статичный | не исполняется |
| сеть | не используется при сборке | `scripts/fx_rate.py` — только ручной запуск |

Секретов, токенов и персональных данных в репозитории нет. Имена ресурсов —
учебные. Адрес для регистрации в Jira задаётся переменной `JIRA_SIGNUP_EMAIL`,
профиль браузера и `creds.json` исключены через `.gitignore`.

## Почему не `defusedxml`

`msproject.read()` разбирает только XML, созданный этой же сборкой. Внешний
недоверенный XML не является сценарием. Если появится импорт чужих файлов,
`defusedxml` нужно добавить вместе с тестом.

## `ruff`

Включены `E7`, `E9`, `F`, `B`: неоднозначный синтаксис, неиспользуемые имена,
ошибки flake8-bugbear. Стилевые правила (длина строки, isort, UP) выключены:
код написан вручную под существующий стиль.

## `bandit`

Пропуски:

- `B110` — `try/except/pass` в COM-автоматизации;
- `B112` — `try/except/continue` там же.

Каждый UI-шаг изолирован: падение одного действия не должно срывать сборку
отчёта. Ошибка пишется в `automation/results/run_log.json`.

## Что проверить перед публикацией

- нет новых зависимостей без записи в двух файлах;
- нет абсолютных путей и имён пользователей;
- `out/` пересобран;
- ссылки в `project.yaml` ведут на существующие файлы;
- `./scripts/check.sh` проходит.
